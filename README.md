# SHOOT_cmzy_REV081 枪管固件

## 1. 项目简介

本项目是基于 `STM32F072C8x` 的枪管控制/裁判通信固件。枪管本身不控制电机或发射执行器，主要负责：

- 读取前、后两颗 VCNL4040 光电传感器；
- 根据两个传感器的先后触发计算射速并统计有效射击次数；
- 通过 CAN 向裁判系统上报射击、状态、启动和故障信息；
- 接收裁判系统的队伍、热量、LED 和传感器校正命令；
- 驱动顶部状态灯和 8 灯热量条；
- 通过独立看门狗和少量复位保留信息处理强故障。

当前固件默认 CAN 波特率为 **500 kbps**。USART2 调试采集接口已从正式固件删除；USART3 仅用于 WS2812 灯条 DMA 输出。

## 1.1 新传感器迁移第一版

当前迁移固件使用 PA4/PA5 DAC（双路 output buffer）驱动红外发射端，PA1/PA3 通过 TIM3 分别以 20 kHz 采样 ADC 两路信号，DMA1 Channel 1 circular 缓冲顺序为 `[ET1, ET2, ...]`。物理通道为 `ET1 -> front`、`ET2 -> rear`；由于沿用旧调试变量命名，`g_dbg_rear_prox` 实际显示 front，`g_dbg_front_prox` 实际显示 rear。本版只提供原始值观测，旧 `vcnl4040`、`shoot_detect`、卡弹/测速算法源文件保留但运行时未启用。

Ozone 变量：`adc_dma_buf[]`、`et1_raw`、`et2_raw`、`adc_half_count`、`adc_full_count`、`adc_error_count`、`ir_dac1_code`、`ir_dac2_code`、`ir_acquisition_ready`。收到 `0x220` 只记录并保持未就绪，不发送虚假的校准成功；本版不产生 `0x230`。CAN PB8/PB9、USART1 PB6/PB7、USART3 PB10 灯效和 IWDG 保留。RGB_TX3 连接新原理图中的单颗 `GL5050RGB01H-T`，USART3 使用 4 Mbps、TX 反相和 DMA 输出。

### 1.2 ADC 实时触发层

当前已加入最小实时检测层，但仍不连接旧的测速和射击应用逻辑：

- 上电后的约 1 s 只采样环境。两路使用 8 位量化直方图取中位数作为静态基线；短暂滑落弹药或噪声只占少量样本，不会直接抬高基线。
- 运行时触发条件为 `ADC >= baseline + 45`。DMA 半区/满区回调在中断上下文扫描刚完成的 8 对样本，越过阈值时每路只置位一次事件并记录计数；主循环通过 `IR_Acquisition_TakeRearEvent()`/`IR_Acquisition_TakeFrontEvent()` 消费事件。
- 触发期间冻结基线；信号回到阈值以下后重新允许下一次触发。未加入滤波、测速、方向配对或 CAN 射击报文，避免在实测波形前引入不可验证的假设。
- 触发层使用慢速（约数百毫秒量级）基线跟踪应对小幅漂移；持续高电平不会被快速吸收，便于后续识别卡弹、遮挡或发射端异常。
- 当前 DMA 块覆盖约 0.4 ms，20 kHz/通道下 20 m/s、10 mm 弹丸的约 0.5 ms 有效区间至少会落入一个完整扫描块；实际漏检裕量仍需实板验证。

## 3. 已实现功能

### 3.1 双传感器射击检测

- 前端传感器：`I2C1`，中断引脚 `PB5`。
- 后端传感器：`I2C2`，中断引脚 `PB12`。
- 传感器采用 VCNL4040 的 `PS_DATA` 和 `AWAY` 中断模式。
- 上电时两路各读取 100 次，平均值作为 baseline；采样间隔为 2 ms，校正约需 200 ms。
- 当前阈值：

  ```text
  THDL = baseline - 20（不足时钳位为 0）
  THDH = baseline
  ```

- 后端先触发、前端后触发时进行配对。
- 两传感器间距为 `50 mm`。
- TIM16 频率为 `20 kHz`，时间分辨率为 `50 μs`。
- 射速公式：

  ```text
  speed(m/s) = 1000 / delta_ticks
  ```

- 当前有效射击速度判定范围为 `1~50 m/s`；默认配对超时为 `50 ms`，因此低于约 `1 m/s` 的目标会在前端到达前被超时清除或被速度范围过滤。
- 有效事件进入 8 项 CAN 发送队列，队列满时丢弃新事件并产生弱故障标志。
- 有效射击的本地灯效与 CAN 发送解耦：即使 CAN 未连接，也会计数、累加热量并启动顶部灯效。

### 3.2 热量机制

- 上电/复位后热量为 0。
- 热量上限为 **200**，热量到 200 后继续射击不会超过 200，但射击总数仍继续增加。
- 每次有效射击热量 `+10`；每满 `1 秒` 自动冷却 `10` 点。
- 达到热量上限时，顶部状态灯显示当前队伍色约 3 秒。
- 枪管只计算和上报热量，不负责停止电机或执行裁判系统的处罚动作。

### 3.3 CAN 通信

CAN 使用标准 11 位数据帧、500 kbps。ID 分层如下：

| 层 | ID | 内容 |
|---|---|---|
| 调试层 | `0x200` | 预留心跳，当前不发送 |
| 故障层 | `0x210~0x212` | 强故障、弱故障、启动帧 |
| 设备层 | `0x220~0x221` | 传感器校正请求和 ACK |
| 应用层 | `0x230~0x234` | 射击事件、状态查询、LED/队伍/热量控制 |

具体 DLC、字节序、掩码和命令格式以 [docs/CAN_PROTOCOL.md](docs/CAN_PROTOCOL.md) 为准。

当前常用报文：

- `0x230`：每次有效射击上报次数、速度、枪管状态和热量。
- `0x231`：请求射击状态；枪管回复 `0x232`。
- `0x220`：请求重新校正传感器；枪管完成后回复 `0x221`。
- `0x233`：设置队伍、热量或执行 LED 测试；成功后回复 `0x234` 原数据。

CAN 未接入时，主功能仍应运行。CAN 发送失败不会主动让枪管复位；但 CAN 长时间不可用可能导致 `0x230` 队列溢出。

### 3.4 LED

- 开机自检：底下 8 灯以当前队伍色全亮 250 ms，随后进入正常显示。
- 顶部状态灯：空闲低亮黄灯，射击成功时闪当前队伍色，热量达到 200 时队伍色常亮约 3 秒。
- 后方 8 灯：按当前热量占 `200` 的百分比显示队伍色。
- 弱故障时：全灯红、蓝、绿快速交替。
- 支持 CAN 队伍设置和 LED 测试命令。
- WS2812 使用 USART3/DMA 输出，灯条忙时不会重复启动新的发送。

### 3.5 故障和复位

- 弱故障通过 `0x211` 上报，采用组合掩码；传感器错误连续确认 3 次后置位。
- HardFault 会把 PC、LR、xPSR 和故障标志写入 `.noinit` 区域，然后软件复位。
- 看门狗复位在下次启动时通过 `0x210` 上报。
- 强故障不在复位前发送；复位后初始化完成时按 `0x210 → 0x212` 顺序发送。
- `.noinit` 不是掉电保持存储，断电后不能保证数据保留；它主要用于软件复位和看门狗复位之间传递信息。

## 4. 使用方法

烧录前确认目标芯片供电正常，6PIN 水晶头线序：GND 12V CANL CANH 12V GND。

### 4.1 CAN 测试

1. CAN 分析仪设置：500 kbps、标准帧、数据帧。
2. 上电后应看到一次 `0x212`；如果上一次发生看门狗/HardFault，先看到 `0x210`，再看到 `0x212`。
3. 发送 `0x231`（DLC 0 或按协议发送 DLC 8）检查 `0x232`。
4. 发送 `0x220` 检查 `0x221` 中的校正前后 baseline。
5. 发送 `0x233` 设置队伍，例如命令字节为 `0x01` 设置红队、`0x02` 设置蓝队，检查 `0x234` 原样 ACK。
6. 让弹丸依次经过后、前传感器，观察 `0x230`、射击计数、速度、热量和顶部灯效。

## 5. 待实现或建议后续处理

以下内容当前没有作为本次交接的完成条件，后续改动前应重新确认需求：

1. **低速射击下限**：当前 50 ms 配对超时使约 1 m/s 以下检测不可靠；如果需要支持低速，应重新定义超时，同时评估计时器回绕和高速连续射击。
2. **传感器校准失败**：短时多次直接通过按钮复位容易导致传感器校准失败闪光，因为I2C设备并未断电重启，建议重新插拔。
3. **传感器检测能力**：仍需实测传感器是否会漏检高速弹丸。
4. **弱故障观测**：当前调试变量仍在主循环中更新，额外 I2C 轮询可能影响实时性；正式比赛版本应单独评估是否保留这些轮询。

## 6. 注意事项

- 修改 CAN ID、DLC、字段或热量范围时，必须同时修改 `Core/Inc/can_protocol.h`、相关实现和 `docs/CAN_PROTOCOL.md`。
- `Byte4~Byte5` 的速度是两字节小端整数，单位为 `0.01 m/s`，不是一个 Byte。
- 当前有效射击顺序是“后端先、前端后”；顺序反过来不会形成有效 `0x230`。
- `barrel_mask` 只表示当前等待配对的槽位，低 5 位有效，不是传感器原始值。
- 不要在传感器 EXTI 中断里执行 I2C 读写、延时、CAN 长阻塞发送或 WS2812 发送。
- CAN 总线应有正确终端电阻和共地；
