# 枪管可靠性实现说明

版本：v3.0  
适用工程：`SHOOT_cmzy_REV081`

> `docs/CAN_PROTOCOL.md` 是 CAN ID、DLC、数据格式和通信行为的唯一权威文档。本文件不重复定义通信协议，只说明故障分类、灯光和复位逻辑。

## 1. 设计目标

比赛中不通过 CAN 诊断具体原因。只需要让裁判系统知道：

- 枪管当前是否存在影响工作的弱故障；
- 枪管是否发生过强故障并已经复位恢复；
- 枪管是否完成本次启动初始化。

具体错误原因仅用于固件内部调试，不作为比赛通信协议要求。

## 2. 故障分类

### 弱故障

弱故障是非 MCU、非 CAN 的异常。主控程序仍在运行，但会干扰枪管工作，例如：

- 前端或后端传感器连续通信失败；
- 发射检测或测速模块异常；
- 关键任务超时；
- 有效射击事件队列溢出；
- 其他不导致 MCU 复位的工作异常。

同类异常连续确认 3 次后进入弱故障状态。单次传感器读失败、单次无效测速和单次触发顺序异常不直接判定整枪故障。

弱故障行为：

```text
立即发送 0x211 弱故障帧
持续故障时每 100 ms 重发
RGB 红、蓝、绿快速交替
故障恢复后停止发送故障帧并恢复正常 RGB 逻辑
不发送恢复帧
```

弱故障掩码的定义以 [CAN_PROTOCOL.md](CAN_PROTOCOL.md) 为准。

### 强故障

强故障是会破坏或停止主控程序运行的异常，例如：

- HardFault；
- 看门狗复位；
- CAN Bus-Off；
- 其他需要 MCU 复位才能恢复的异常。

强故障的关键规则：

```text
复位前不发送强故障 CAN 帧
必要时 RGB 红、蓝、绿快速交替约 2 秒
执行复位
重新完成初始化
发送 0x210 强故障复位后上报帧
随后发送 0x212 上电/初始化完成帧
```

如果 CAN Bus-Off 导致发送通道不可用，复位前的三色灯只用于本地提示；真正的强故障帧在复位后 CAN 初始化成功时发送。

强故障掩码的定义以 [CAN_PROTOCOL.md](CAN_PROTOCOL.md) 为准。

## 3. 上电与初始化

所有必要初始化完成后发送一次 `0x212`，该帧表示枪管已经完成本次启动并进入运行状态。

```text
正常启动：0x212
强故障复位后：0x210 → 0x212
```

异常复位后 RGB 不显示额外警告，恢复正常自动逻辑。

## 4. 看门狗

看门狗用于处理主循环卡死、HardFault 后死循环和关键任务无法恢复等情况。

- 只允许在主循环完成关键健康检查后喂狗；
- 不在普通中断中喂狗；
- 主循环卡死时应停止喂狗，让 IWDG 复位 MCU；
- 启动时读取复位原因，若识别到看门狗复位，则在初始化完成后通过 `0x210` 上报。

阈值调试模式中 `debug_flag=true`：本次固件默认开启。该模式不启动 IWDG，并禁止 CAN Bus-Off 的三色提示后自动复位；`0x200` 调试心跳 ID 保留但不发送。HardFault 无法安全继续执行，仍会立即复位。

## 5. HardFault 保存

HardFault 中不尝试发送 CAN。应先保存最小现场并复位，启动后再上报。

建议内部保存：

- HardFault 标志；
- PC；
- LR；
- xPSR；
- MSP/PSP；
- 复位原因；
- 简单 magic 和 CRC。

这些信息只用于调试，不增加比赛 CAN 报文内容。

STM32F072C8U6 的 RTC 备份寄存器可保存少量复位摘要；完全掉电时是否保留取决于 VBAT 和备份域供电。详细保存方案不属于当前比赛协议的必要功能。

## 6. 权威协议索引

所有 ID 和报文定义只看：

[CAN_PROTOCOL.md](CAN_PROTOCOL.md)

当前协议分层为：

```text
0x200：调试心跳
0x210：强故障复位后上报
0x211：弱故障
0x212：上电/初始化完成
0x220：请求传感器校正
0x221：传感器校正 ACK
0x230：有效射击事件
0x231：射击状态查询
0x232：射击状态回复
0x233：LED/队伍/热量控制
0x234：LED/队伍/热量控制 ACK
```
