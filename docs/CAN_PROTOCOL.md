# 枪管 CAN 通信协议

版本：v3.7　　适用工程：`SHOOT_cmzy_REV081`

本文档与当前固件实现对应，是 CAN 报文的最终定义。协议为经典 CAN、标准 11 位 ID、数据帧（`CAN_RTR_DATA`），波特率 500 kbps。多字节整数均为小端序。CAN ID 越小，仲裁优先级越高。

## 1. ID 分层与分配

| 层 | ID 范围 | 说明 |
|---|---|---|
| 调试层 | `0x20x` | 预留调试报文 |
| 故障层 | `0x21x` | 强故障、弱故障、启动状态 |
| 设备层 | `0x22x` | 传感器校正 |
| 应用层 | `0x23x` | 射击状态、LED/队伍/热量控制 |

| ID | 方向 | 报文 | DLC | 行为 |
|---:|---|---|---:|---|
| `0x200` | 枪管→上位机 | 调试心跳（预留） | 8 | 当前固件不发送 |
| `0x210` | 枪管→上位机 | 强故障复位后上报 | 1 | 复位后初始化完成时发送 |
| `0x211` | 枪管→上位机 | 弱故障状态 | 1 | 故障发生、持续或清除时发送 |
| `0x212` | 枪管→上位机 | 上电/初始化完成 | 0 | 初始化完成后发送一次 |
| `0x220` | 上位机→枪管 | 请求传感器校正 | 0 | 收到后在主循环执行 |
| `0x221` | 枪管→上位机 | 传感器校正 ACK | 8 | 校正完成或失败后发送 |
| `0x230` | 枪管→上位机 | 有效射击事件 | 8 | 每次有效射击发送 |
| `0x231` | 上位机→枪管 | 射击状态查询 | 0 或 8 | 收到后回复 `0x232` |
| `0x232` | 枪管→上位机 | 射击状态回复 | 8 | 回复 `0x231` |
| `0x233` | 上位机→枪管 | LED/队伍/热量控制 | 8 | 有效命令执行 |
| `0x234` | 枪管→上位机 | 控制命令 ACK | 8 | 原样回显 `0x233` 数据 |


## 2. 故障与启动报文

### `0x210` 强故障复位后上报

`DLC=1`，`Byte0` 为组合掩码：`bit0` HardFault，`bit1` 看门狗复位，`bit2` CAN Bus-Off，`bit3` 其他异常复位，`bit7` 未定义强故障。CAN Bus-Off 只在被明确判定为需要复位的场景下进入强故障复位流程；未接 CAN 节点时，枪管继续独立运行，不因无 ACK 而复位。

强故障发生时不发送 CAN 故障帧；先保存标志并复位，重新初始化成功后按 `0x210`、`0x212` 顺序发送。HardFault 现场的 PC/LR/xPSR 仅保存在内部调试记录中。

### `0x211` 弱故障状态

`DLC=1`，`Byte0` 为组合掩码：`bit0` 前端传感器，`bit1` 后端传感器，`bit2` 发射检测/测速，`bit3` 关键任务，`bit4` 事件队列，`bit7` 未定义弱故障。

同类异常连续确认 3 次后置位；故障持续时约每 100 ms 重发。故障恢复后发送 `Byte0=0` 清除状态。弱故障期间顶部状态灯红、蓝、绿快速交替。

### `0x212` 启动完成

`DLC=0`。所有必要初始化和启动校正完成后发送一次。正常启动只发送 `0x212`；强故障复位后的启动顺序为 `0x210 → 0x212`。

## 3. 设备层：传感器校正

### 请求 `0x220`

仅接受标准数据帧、`DLC=0`。收到后由主循环启动约 1 s ADC 重校准；重校准期间关闭射击事件生成。前、后 ADC 基线分别使用采样窗口的稳健中值，完成后恢复阈值检测。

阈值为：

```text
front_trigger = front_baseline + 60 ADC
rear_trigger  = rear_baseline + 18 ADC
```

比较当前样本与阈值后，基线才按约 `1/2048` 的慢速系数更新。校准过程不在 CAN 接收中断中执行。

### ACK `0x221`

`DLC=8`，四个 `uint16` 小端字段：`Byte0~1` 前端校正前 baseline，`Byte2~3` 前端校正后 baseline，`Byte4~5` 后端校正前 baseline，`Byte6~7` 后端校正后 baseline。

## 4. 应用层：射击状态

### 有效射击事件 `0x230`

后端为可选测速候选，前端有效脉冲始终产生一个射击事件；后端峰值必须先于前端峰值，且峰值时间差在 `3333~25000 μs` 内才提供有效速度。`Byte0~3` 为累计射击次数，`Byte4~5` 为本次速度，编码为 `uint16 = round(m/s × 10)`（分辨率 0.1 m/s）；无有效后端匹配或速度超出 `2~15 m/s` 时填 `0xFFFF`。`Byte6` 固定为 `0`，`Byte7` 为本次射击后的热量（0~200）。射击事件只在主循环消费一次；CAN 未连接或暂时发送失败不影响本地计数、热量和灯效，事件会在 8 项应用队列中保留等待发送；队列满后新增报文可丢失并触发队列弱故障，累计次数、热量和灯效仍更新。此实现不保证无限断连期间每发报文均可补发。

采样间隔为 50 μs（约 20 kHz/通道）；速度计算为 `v = 50 mm / peak_delta`。

### 查询 `0x231` 与回复 `0x232`

`0x231` 仅接受标准数据帧且 DLC 为 0 或 8；DLC=8 时数据应填 0。接收中断只登记请求，主循环再发送 `0x232`，避免中断内发帧与其他节点争用邮箱。`0x232` 的 Byte0~3 为累计次数，Byte4~5 为最近速度，编码为 `uint16 = round(m/s × 10)`（分辨率 0.1 m/s），无效时为 `0xFFFF`，Byte6 固定为 `0`，Byte7 为当前热量。

### 热量

上电/复位后热量为 0；每次有效射击加 10，最大钳位为 200，但达到 200 后仍继续计数和上报；每满 1 秒自动减 10，最低为 0。枪管只计算和上报热量，不执行裁判系统的 3 秒射击处罚。

## 5. LED、队伍和热量控制

### 命令 `0x233`

必须为标准数据帧、`DLC=8`：Byte0 为命令，Byte1 为参数，Byte2~7 保留并填 0。

| Byte0 | 功能 | Byte1 |
|---:|---|---:|
| `0x00` | 恢复自动模式 | 无 |
| `0x01` | 设置红队 | 无 |
| `0x02` | 设置蓝队 | 无 |
| `0x03` | 设置当前热量 | `0~200` |
| `0x10` | 全绿测试 | 无 |
| `0x11` | 全红测试 | 无 |
| `0x12` | 全蓝测试 | 无 |
| `0x1F` | 全灭 | 无 |

`0x03` 越界、未知命令或格式错误时忽略且不 ACK。有效命令执行后，以 `0x234` 原样回显 8 字节数据。正常显示时后段 8 灯按 `0~200` 热量范围显示队伍色（即热量百分比）；顶部状态灯空闲为低亮黄，热量达到 200 时队伍色常亮约 3 秒。

设置队伍（`0x01`/`0x02`）后进入自动显示，继续响应射击闪灯和热量变化。每次有效射击令顶部状态灯以队伍色闪亮 100 ms；连续射击会重新开始这段闪亮时间。CAN 测试命令（`0x10`/`0x11`/`0x12`/`0x1F`）保持手动显示，发送 `0x00` 恢复自动显示。当前队伍色为红队粉红、蓝队湖蓝。

物理输出：逻辑第 0 灯通过 RGB_TX3/PB10 连接板载 GL5050RGB01H-T（RGB 顺序、USART3、DMA1 CH2）；逻辑第 1~8 灯通过 WAFER-GH1.25-4PWB 的 RGB_TX2/PB6 输出到八颗串联 WS2812（GRB 顺序、USART1、DMA1 CH4）。两路均采用 4 Mbaud、8N1、8 倍过采样和 TX 反相编码 WS2812 波形；底层负责物理映射，上层灯效继续使用逻辑 9 灯。RGB_RX2/PB7 为端子接收线，保留初始化。上电两路全部亮队伍色 250 ms，底部灯条显示热量进度，CAN 测试颜色同时作用于两路。
